# 사용자 스토리

## US-01 관리자는 로그인 후에, 글쓰기 기능으로 글을 직접 쓸 수 있다

| 항목 | 내용 |
|---|---|
| 누가 | 관리자 (계정 `admin` 하나뿐) |
| 무엇을 | 로그인한 뒤 글쓰기 화면에서 글을 직접 쓰고 저장한다 |
| 왜 | 외부 도구 없이 내 블로그에 바로 글을 올리기 위해서 |
| 범위 | 새 글 작성·저장까지. 수정·삭제는 다음 스토리(글 관리)에서 다룬다 |

### 화면 흐름

1. 관리자 로그인 (`/login`)
2. 상단 메뉴의 **글쓰기** 버튼 (`/write`)
3. 제목, 카테고리, 공개 범위(공개 / 나만보기), 본문 입력
4. **저장** → 글 상세 화면(`/post?id=…`)으로 이동

시안: 관리자 로그인 → 글쓰기 → 글 상세 (디자인 캔버스의 `Login`, `Write`, `Post`)

### 인수 조건

| # | 조건 (Given / When / Then) | 확인 방법 | 결과 |
|---|---|---|---|
| 1 | 로그인하지 않았다면, 글 저장을 요청해도 거부된다 (401) | `POST /api/posts` 쿠키 없이 | 통과 |
| 2 | 아이디나 비밀번호가 틀리면 로그인되지 않는다 (401) | `POST /api/auth/login` 틀린 비번 | 통과 |
| 3 | 올바른 계정으로 로그인하면 글쓰기를 쓸 수 있다 (200) | 로그인 후 쿠키 발급 | 통과 |
| 4 | 로그인한 관리자가 제목·본문·카테고리·공개 범위를 채워 저장하면 글이 만들어진다 (201) | `POST /api/posts` | 통과 |
| 5 | 제목이나 본문이 비어 있으면 저장되지 않고 이유를 알려 준다 (400) | 빈 제목 전송 | 통과 |
| 6 | 공개로 저장한 글은 비로그인 방문자의 글 목록에 보인다 | `GET /api/posts` | 통과 |
| 7 | 나만보기로 저장한 글은 방문자에게 보이지 않고(404), 관리자에게만 열린다 | `GET /api/posts/:id` | 통과 |
| 8 | 다른 사이트에서 보낸 저장 요청은 막힌다 (403) | 다른 Origin 헤더 | 통과 |

확인 환경: 로컬(`wrangler pages dev`)에서 API를 직접 호출했습니다. 브라우저 화면에서 직접 눌러 보는 확인은 아래 체크리스트로 남겨 둡니다.

### 직접 확인 체크리스트 (브라우저)

- [ ] `/write`를 로그아웃 상태로 열면 로그인 화면으로 이동한다
- [ ] 로그인 후 상단에 **글쓰기** 버튼이 보인다
- [ ] 저장하면 방금 쓴 글의 상세 화면이 열린다
- [ ] 나만보기 글에 자물쇠 배지가 붙고, 로그아웃하면 목록에서 사라진다

### 구현 위치

| 역할 | 파일 |
|---|---|
| 로그인 화면 | `public/login.html`, `functions/api/auth/login.js` |
| 글쓰기 화면 | `public/write.html`, `public/app.js` |
| 글 저장 API | `functions/api/posts/index.js` (POST) |
| 입력 검사 | `lib/util.js`의 `validatePost` |
