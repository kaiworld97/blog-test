# 머니로그 GA4 이벤트 택소노미와 설정 가이드

측정 ID: `G-JFCEXBGL26` (코드는 `public/analytics.js`, 홈과 글 상세에서만 동작)

> 상태: "자동 수집"과 "커스텀 이벤트"(3-2) 모두 배포되어 동작합니다.

## 1. 무엇을 알고 싶은가 (측정 질문)

이벤트는 "궁금한 것"에서 거꾸로 정합니다.

| # | 질문 | 이걸로 결정할 일 |
|---|---|---|
| Q1 | 사람들이 어디서 들어오나? (검색, SNS, 직접) | 어느 채널에 글을 공유할지 |
| Q2 | 어떤 주제(카테고리)가 많이 읽히나? | 다음에 쓸 글의 주제 |
| Q3 | 글을 끝까지 읽나, 앞부분만 보고 나가나? | 글 길이·구성 개선 |
| Q4 | 홈에서 글 목록으로, 목록에서 글로 잘 넘어가나? | 홈 화면·제목 개선 |
| Q5 | 어떤 글이 인기 있고, 계속 읽히나? | 인기 글 상단 노출, 후속 글 |

## 2. 이름 규칙

- 이벤트 이름: 영어 소문자 + 밑줄, `동사_대상` 형태 (`select_category`, `read_complete`)
- GA4가 정한 추천 이벤트 이름이 있으면 그대로 씁니다 (`select_content`, `share`, `login`). 그래야 기본 보고서가 알아서 채워집니다.
- 파라미터 이름도 소문자 + 밑줄. 값은 글자 수 100자 이내
- 개인정보(이메일, 이름, 비밀번호 등)는 어떤 이벤트에도 넣지 않습니다
- 관리자 화면(로그인·글쓰기·내 글)은 GA를 로드하지 않으므로 이벤트도 없습니다

## 3. 이벤트 목록

### 3-1. 자동 수집 (코드 없이 이미 동작)

| 이벤트 | 언제 | 비고 |
|---|---|---|
| `page_view` | 페이지를 열 때 | 글 상세는 `page_location`에 `?id=N`이 포함됨 |
| `session_start`, `first_visit` | 세션 시작, 첫 방문 | |
| `user_engagement` | 페이지를 열어 둔 시간 | |
| `scroll` | 페이지 90% 지점까지 스크롤 | 향상된 측정 켜진 경우 |
| `click` (outbound) | 외부 링크 클릭 | 향상된 측정 켜진 경우 |

### 3-2. 커스텀 이벤트 (설계 — 구현 대기)

| 이벤트 | 언제 보내나 | 파라미터 | 답하는 질문 |
|---|---|---|---|
| `select_category` | 홈에서 카테고리 칩을 누를 때 | `category` (예: 저축, 전체) | Q2, Q4 |
| `select_content` | 홈 목록에서 글 카드를 눌러 글로 이동할 때 | `content_type`=`post`, `content_id`(글 번호), `category`, `list_position`(몇 번째) | Q4, Q5 |
| `read_progress` | 글 상세에서 본문 25·50·75·100% 지점을 처음 지날 때 | `percent`(25/50/75/100), `content_id`, `category` | Q3 |
| `read_complete` | 글 상세에서 본문 끝까지 내리고 20초 이상 머물 때 | `content_id`, `category`, `read_seconds` | Q3, Q5 |
| `share` | (공유 버튼을 만들 경우) 링크 복사·공유 클릭 | `method`(copy_link 등), `content_type`=`post`, `item_id` | Q1 |

3-2의 이벤트는 모두 `content_id`와 `category`를 같은 이름으로 보내므로 한 기준으로 묶어 볼 수 있습니다. `page_view`에는 이 값이 없습니다(글 내용을 불러온 뒤에야 알 수 있기 때문).

> 구현 상태: 3-2의 이벤트 4개(`select_category`, `select_content`, `read_progress`, `read_complete`)는 구현·배포됐습니다. `share`는 공유 버튼이 없어 아직 없습니다. 관리자 본인 글을 볼 때는 `read_*` 이벤트를 보내지 않습니다. 코드: `public/analytics.js`(`window.track`), `public/app.js`(`trackReading`).

### 3-3. 보내지 않는 것

- 로그인, 글 작성·수정·삭제: 관리자만 쓰는 화면이고 GA를 로드하지 않습니다
- 글 제목 전체, 본문: 개인정보는 아니지만 값이 너무 길고 필요하지 않습니다. 글 번호(`content_id`)로 충분합니다

## 4. 핵심 이벤트(전환) 정하기

GA4에서는 "전환"이 "핵심 이벤트(Key event)"로 이름이 바뀌었습니다.

| 핵심 이벤트 | 이유 |
|---|---|
| `read_complete` | 이 블로그의 성공 = "글을 끝까지 읽었다" |

처음에는 하나만 지정합니다. 방문자가 늘고 구독·뉴스레터 같은 기능이 생기면 그때 추가합니다.

## 5. 맞춤 정의(Custom definitions)

파라미터를 보고서에서 쓰려면 GA에 등록해야 합니다. 이름은 GA가 표시할 이름, 이벤트 매개변수는 코드의 파라미터 이름과 정확히 같아야 합니다.

| 유형 | 측정기준 이름 | 범위 | 이벤트 매개변수 |
|---|---|---|---|
| 측정기준 | 글 카테고리 | 이벤트 | `category` |
| 측정기준 | 글 번호 | 이벤트 | `content_id` |
| 측정기준 | 읽은 비율 | 이벤트 | `percent` |
| 측정기준 | 목록 위치 | 이벤트 | `list_position` |
| 측정항목 | 읽은 시간(초) | 이벤트(표준) | `read_seconds` |

측정기준은 속성당 최대 50개(이벤트 범위)입니다. 위 4개 + 측정항목 1개면 충분합니다.

## 6. GA 설정, 순서대로

### 6-1. 속성·데이터 스트림 확인

1. [analytics.google.com](https://analytics.google.com) → 관리(왼쪽 아래 톱니바퀴)
2. **속성 설정**: 보고 시간대 `대한민국`, 통화 `KRW (₩)`
3. **데이터 스트림** → 웹 스트림 선택
   - URL이 `https://blog-test-a09.pages.dev`인지 확인
   - 측정 ID가 `G-JFCEXBGL26`인지 확인

### 6-2. 향상된 측정 (스트림 화면)

"향상된 측정"을 켜고 톱니바퀴를 눌러 세부 항목을 정합니다.

| 항목 | 설정 | 이유 |
|---|---|---|
| 페이지 조회 | 켬 | 기본 |
| 스크롤 | 켬 | 90% 스크롤 자동 수집 |
| 이탈 클릭 | 켬 | 외부 링크 클릭 |
| 사이트 검색 | 끔 | 사이트에 검색창이 없음 |
| 동영상 참여, 파일 다운로드 | 끔 | 해당 콘텐츠 없음 |
| 양식 상호작용 | 끔 | 공개 페이지에 양식이 없음 |
| 페이지 변경(기록 이벤트) | 끔 | 이 사이트는 페이지마다 새로 로드되어 중복 집계될 수 있음 |

### 6-3. 데이터 보관 기간

관리 → 데이터 수집 및 수정 → **데이터 보관** → 이벤트 데이터 보관을 `14개월`로 바꿉니다. (기본 2개월이면 탐색 보고서에서 오래된 데이터가 사라집니다.)

### 6-4. 내부 트래픽 제외 (중요)

내가 사이트를 열 때마다 방문으로 잡히지 않게 합니다.

1. 데이터 스트림 → **태그 설정 구성** → **내부 트래픽 정의** → 만들기
   - 규칙 이름: `내 IP`, traffic_type 값: `internal`, IP 주소: 내 공인 IP (검색창에 "내 아이피"로 확인)
2. 관리 → 데이터 수집 및 수정 → **데이터 필터** → `Internal Traffic` 필터
   - 처음에는 **테스트** 상태로 두고 `traffic_type`이 `internal`로 잡히는지 확인한 뒤 **활성**으로 바꿉니다
3. 집·회사 IP가 바뀌는 환경이면 규칙에 IP를 추가하거나, 아래 6-8의 DebugView 확인용으로만 쓰고 보고서는 필터로 거릅니다

### 6-5. 맞춤 정의 등록

관리 → 데이터 표시 → **맞춤 정의** → 맞춤 측정기준 만들기. 5장의 표대로 4개, 맞춤 측정항목 1개를 만듭니다. 한 번 만들면 이벤트가 수집되기 시작한 뒤에 보고서에 나타납니다(최대 24시간).

### 6-6. 핵심 이벤트 지정

관리 → 데이터 표시 → **핵심 이벤트** → 새 핵심 이벤트 → `read_complete`. 이벤트가 한 번이라도 들어온 뒤에야 목록에 보이므로, 커스텀 이벤트를 배포한 뒤에 설정합니다. (이벤트가 안 보이면 이름을 직접 입력해 만들 수 있습니다.)

### 6-7. 도움이 되는 연동

| 연동 | 하는 일 | 방법 |
|---|---|---|
| Search Console | 어떤 검색어로 들어왔는지 | 관리 → 제품 링크 → Search Console 링크. 먼저 Search Console에서 `https://blog-test-a09.pages.dev`를 등록하고 sitemap(`/sitemap.xml`)을 제출 |
| Google 신호 | 연령·관심사 | 개인정보 이슈가 있으므로 끄는 것을 권장 |

### 6-8. 동작 확인 (DebugView)

1. 크롬 확장 **Google Analytics Debugger**를 설치하고 켭니다
2. 사이트를 열고 GA → 관리 → **DebugView**에서 내 기기의 이벤트가 실시간으로 뜨는지 봅니다
3. 확인할 것: `page_view`, 카테고리 칩 클릭 시 `select_category`, 글 끝까지 스크롤 시 `read_progress`/`read_complete`와 파라미터 값
4. 일반 보고서는 수 시간~1일 늦습니다. 바로 확인하려면 **보고서 → 실시간**을 봅니다

## 7. 보고서 보는 법 (Q1~Q5와 연결)

| 질문 | 어디서 | 보는 법 |
|---|---|---|
| Q1 유입 채널 | 보고서 → 획득 → 트래픽 획득 | 기본 채널 그룹: Organic Search / Social / Direct |
| Q2 인기 카테고리 | 탐색 → 자유 형식 | 행: 글 카테고리, 값: 이벤트 수(`read_complete` 필터) |
| Q3 끝까지 읽는 비율 | 탐색 → 유입경로 탐색 분석 | 단계: `page_view` → `read_progress`(50) → `read_complete` |
| Q4 홈→글 이동 | 탐색 → 유입경로 | 단계: 홈 `page_view` → `select_content` → 글 `page_view` |
| Q5 인기 글 | 보고서 → 참여도 → 페이지 및 화면 | 페이지 경로 + 쿼리(`?id=N`)별 조회수. 쿼리가 합쳐져 보이면 맞춤 측정기준 `글 번호`로 탐색 |

> GA4는 기본적으로 URL의 쿼리(`?id=2`)를 `page_location`에는 남기지만 "페이지 경로" 보고서에서는 떼어 버릴 수 있습니다. 글별 집계는 `content_id` 측정기준을 쓰는 것이 정확합니다.

## 8. 개인정보와 동의

- 이 사이트는 로그인한 방문자 정보를 쓰지 않고, 회원 가입이 없습니다. 이벤트에 개인정보를 넣지 않습니다.
- `analytics.js`는 브라우저의 추적 금지(DNT) 설정을 따릅니다.
- 한국 방문자만 대상이면 별도 동의 배너는 필수는 아니지만, 쿠키 사용 안내 한 줄을 푸터에 두는 것을 권합니다. EU 방문자를 받을 계획이면 동의 모드(Consent Mode)가 필요합니다.
